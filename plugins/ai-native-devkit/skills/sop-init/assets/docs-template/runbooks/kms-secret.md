# KMS 凭证管理和接入

## 适用范围

用于通过 AWS Secrets Manager、AWS KMS、Google Secret Manager、Azure Key Vault、HashiCorp Vault、SOPS 或组织自建平台创建、查看、接入和轮转敏感配置。

业务数据加解密、证书签发和硬件密钥托管可能需要专项 runbook。

## 来源和时效

这是公共模板，不绑定任何公司平台。具体地址、SDK、审批流程、密钥策略和轮转能力以项目所在组织的密钥管理平台当前文档为准。

## 核心概念

- 环境：开发、测试、预发和生产应相互隔离。
- 项目或命名空间：资源和权限隔离边界。
- 身份：工作负载、服务账号、IAM role、Access Key 或平台等价身份。
- Secret：托管敏感值的资源，通常包含版本。
- Version：敏感值的明确版本。运行时获取敏感信息应尽量引用可审计版本。
- Key：保护 Secret 或执行加解密的密钥材料或主密钥。

## 必要输入

- 环境 `<ENV>`、项目或命名空间 `<SECRET_SCOPE>`、凭证用途和 Owner。
- 凭证类型、编码契约、访问身份和最小权限范围。
- 新旧 Version、消费方、切换顺序、验证方式和失效计划。
- 应用接入方式、运行区域和对应 endpoint。

## 安全边界

- 不在代码、普通配置、文档、Issue、日志或回复中保存密钥、凭证明文或解密结果。
- 不把敏感值放入普通配置平台代替密钥管理系统。
- 不跨环境或跨项目猜测复用身份、Secret ID、Key ID 或 endpoint。
- 获取托管凭证时优先使用明确版本或受控别名，避免不可审计的“取最新”。
- 调试输出必须先脱敏。不能为了排障展示明文。

## 新增凭证

1. 进入目标环境的密钥管理平台，选择或创建正确项目或命名空间。
2. 确认管理员、审批路径和最小权限身份可用。
3. 选择或创建保护凭证的 Key 或策略，核对用途和状态。
4. 创建 Secret，填写不泄露实际值的名称、用途和 Owner。
5. 写入敏感值时使用平台推荐的编码和导入方式。消费端取回后只做约定次数的解码。
6. 保存非敏感坐标：环境、命名空间、Secret ID、Version、用途和 Owner。不要保存凭证值。
7. 需要审批的更新或授权按平台流程提交，由独立审批人完成。

预期结果：凭证有明确环境、项目归属、版本、授权和审计记录，明文没有进入代码仓库或普通文档。

## 查看凭证

1. 默认只查看环境、命名空间、名称、Secret ID、版本列表、当前状态、授权、更新时间和审计记录。
2. 核对应用配置引用的是明确 Version 或受控别名，而不是未审计的隐式最新值。
3. 只有业务任务确实需要且权限允许时，才由受控应用或官方工具获取值；不要在对话或截图中展示明文。
4. 查看结果只记录元数据结论，例如“目标版本存在且已授权”，不记录值本身。

## 应用接入

1. 选择组织支持的接入形态：SDK、sidecar、agent、本地挂载文件或平台注入环境变量。
2. 通过运行时身份或安全注入提供访问凭证，不把身份密钥提交到仓库。
3. 初始化超时、缓存、重试和日志策略；日志不得输出 Secret 值。
4. 启动时可预加载关键凭证；预加载失败是否阻断启动按依赖强度明确处理。
5. 健康检查要证明“取值并被依赖使用成功”，不能只证明 SDK 或 agent 初始化成功。

## 版本轮转

1. 盘点全部消费方和当前 Version，确认旧版本失效后哪些旧镜像会无法启动。
2. 在上游系统生成新值或在密钥平台创建新版本，保持旧版本暂时可用。
3. 更新预发消费者引用的明确 Version，验证取值、解码和真实依赖连接。
4. 按发布流程切换生产消费者，监控错误率和依赖健康。
5. 全部消费者稳定后再将旧版本失效，并记录切换时间和证据。
6. 失效后，代码镜像回滚不等于配置回滚。旧镜像若引用旧 Version 会启动失败，必须准备兼容镜像或重新启用旧版本的受控方案。

## 失败处理

- 认证失败：核对环境、命名空间、身份状态和授权，不输出 Secret 排障。
- 找不到凭证或版本：核对 Secret ID、Version 和环境，不改成无版本查询规避错误。
- endpoint 不可达：核对运行区域、网络和平台状态，不在生产容器使用测试 endpoint。
- 解码失败：停止使用该值，检查创建时编码契约和版本，不做多次猜测性解码。
- 轮转后依赖失败：切回仍有效的上一 Version 或恢复上游旧值，验证消费者恢复后再分析。

## 项目化补充

在具体项目中补充密钥平台入口、身份模型、SDK 文档、权限申请方式、轮转频率、审计要求和应急联系人。
